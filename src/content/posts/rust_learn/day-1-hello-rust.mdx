# Day 1 · Hello Rust

今天的目标很朴素:把 Rust 装起来,跑通 hello world,理解 cargo 在干什么。代码在 [`day1/`](https://github.com/RoddyH17/rust_learn/tree/main/day1)。

## 装环境:一条命令 vs 一个下午

```bash
curl --proto '=https' --tlsv1.2 https://sh.rustup.rs -sSf | sh
```

装完就有 `rustc`(编译器)、`cargo`(构建+包管理)、`rustup`(工具链版本管理)、`clippy`(linter)、`rustfmt`(格式化)、`rust-analyzer`(LSP)。全套,官方的,版本互相咬合。

回想我配 C++ 环境的经历:编译器选 g++ 还是 clang,构建系统写 CMake,包管理在 vcpkg / conan / 手动 git submodule 之间纠结,格式化配 clang-format,linter 配 clang-tidy——每一件都是独立决策,每两件之间都可能打架。**C++ 的工具链是二十年生态演化的地质沉积层,Rust 的工具链是一次性设计出来的。** 这是今天最大的体感差异。

(小插曲:rustup 想往 `~/.tcshrc` 追加 PATH 时报了 Permission denied。zsh 用户完全不受影响,它真正写的是 `~/.zshenv`。)

## hello world:宏,不是函数

```rust
fn main() {
    println!("Hello, world!");
}
```

那个 `!` 不是装饰——`println!` 是**宏**,编译期展开,格式串在**编译期**被检查:

```rust
println!("day {}", 1);      // OK
println!("day {}");          // 编译错误:参数数量不匹配
```

C++ 里 `printf("%s", 42)` 是运行期未定义行为,`std::format`(C++20)才补上了编译期检查——Rust 从第一天就是这样。

## cargo:它替代的不是 make,是整个"项目管理"这件事

```bash
cargo new hello_cargo   # 项目骨架 + git init
cargo run               # 编译 + 运行
cargo check             # 只做类型检查,快,日常写代码用这个
cargo build --release   # 优化编译,≈ g++ -O3
```

`Cargo.toml` 五行,声明式,依赖写一行 `rand = "0.8"` 就完事。对比我写过的最小可用 CMakeLists.txt——`cmake_minimum_required`、`project`、`add_executable`、`target_link_libraries`,还没算 find_package 失败时的一小时人生。

| | C++ | Rust |
|---|---|---|
| 编译器 | g++ / clang / msvc,自选 | rustc,唯一 |
| 构建 | CMake / Make / Bazel… | cargo,唯一 |
| 包管理 | vcpkg / conan / submodule | cargo,唯一 |
| 依赖锁定 | 靠自觉 | Cargo.lock,自动 |
| dev/release | 自己配 CMAKE_BUILD_TYPE | 内置两个 profile |

## 今天的反思

工具链的统一不只是"方便"。C++ 里每个项目的构建方式都略有不同,意味着**阅读陌生项目的第一小时花在理解它怎么编译**;Rust 里任何项目都是 `cargo build`,这一小时直接还给你。对我这种想快速读大量开源代码学习的人,这可能比语言特性本身更值钱。

明天进入正题:变量、可变性、所有权第一课——那才是 Rust 和 C++ 真正分道扬镳的地方。C++ 说"你可以做任何事,后果自负";Rust 说"先证明给编译器看"。
