# 00 · 绑定、可变性与表达式

> 一句话:Rust 里 `let` 是**绑定**不是赋值,几乎所有东西都是**表达式**而不是语句。这两件事一起决定了代码的形状。

## Shadowing 与 Mutation:两件被同一个符号掩盖的事

```rust
// shadowing:新变量,允许换类型
let spaces = "   ";
let spaces = spaces.len();     // ✓ &str → usize

// mutation:同一个变量,类型必须不变
let mut spaces = "   ";
// spaces = spaces.len();      // ✗ 类型不匹配
```

第二个 `let` 造的是一个**全新的变量**,只是恰好同名;旧的 `spaces`(`&str`)从此不可达。而 `mut` 版本是在同一个内存位置上写新值,所以类型必须守恒。

> **抽象断裂点｜同一性问题被写进了语法**
> 这两行代码在别的语言里长得几乎一样,在 Rust 里却是两个不同的哲学立场:
>
> - **shadowing** = 这是一个新对象,恰好占用了旧名字。旧对象没有被改变,只是不再被指称。
> - **mutation** = 还是那个对象,但它现在的状态不同了。
>
> 这正是忒修斯之船的两种回答,被编译器强制你在每一行做出选择。而 Rust 的默认值是前者:不写 `mut` 就不能改,所以**默认的世界观是「东西不变,变的是我们指向谁」**——和 **Lecture 1 - What is a Functional Language** 里函数式语言的立场一致。
> 长线上值得注意的是:一门语言让哪一种更容易写,就在训练使用者默认用哪一种方式思考变化。「用新值遮蔽旧值」和「原地更新」在版本控制(不可变提交 vs 覆盖文件)、数据库(append-only log vs update in place)、甚至个人笔记系统里都是同一组选项。

## const 与 static

|          | 何时求值 | 存在哪                        | 能否 `mut`                 |
| -------- | -------- | ----------------------------- | -------------------------- |
| `let`    | 运行时   | 栈                            | 加 `mut` 可以              |
| `const`  | 编译期   | 无固定地址,**每处使用被内联** | 不能                       |
| `static` | 编译期   | 有固定地址,整个程序一份       | `static mut` 需要 `unsafe` |

`const` 像一个命名的字面量,`static` 像一块全局内存。差别在**有没有身份(地址)**——这也是为什么 `static mut` 是 unsafe 的:全局可写内存天然违反「共享 + 可变」的禁令。

## 语句与表达式

- **语句(statement)**:执行一个动作,不产生值。`let x = 6;` 是语句。
- **表达式(expression)**:求值出一个结果。`5`、`x + 1`、一个块、一次 `if`、一次 `match` 都是。

块的值是它最后一个**不带分号**的表达式:

```rust
let y = {
    let x = 3;
    x + 3          // 没有分号 → 这是块的值
};                 // y == 6
```

分号把表达式变成语句,值被丢弃,块的类型变成 `()`。这条规则解释了两个日常错误:

```rust
fn five() -> i32 { 5 }     // ✓ 尾表达式即返回值
fn broken() -> i32 { 5; }  // ✗ 加了分号,实际返回 ()
```

以及 **所有权与内存模型** 里那个「返回 `s` 时不能加分号」。

`if` 也是表达式:

```rust
let number = if condition { 5 } else { 6 };
```

因此各分支的类型必须一致——这不是额外规定,是「表达式必须有一个类型」的直接推论。

> **抽象断裂点｜表达式化让「值」和「控制流」合并**
> 在 C 里,`if` 是控制流,`?:` 是表达式,两者是不同的东西,所以有了三元运算符这种妥协。Rust 取消了这个分野:`if`、`match`、`loop`(带 `break value`)、块,全都直接求值。三元运算符因此不需要存在。
> 这个统一的深处是 λ 演算:如果一切都是表达式,程序就是一棵可求值的树,而不是一串按顺序执行的指令。**「程序是什么」的两种模型——指令序列 vs 可求值的项——在这一行语法上分叉。** 见 **Lecture 1 - What is a Functional Language** 里 `what to compute` 与 `how to compute` 的对照。

## 流程控制

三种循环各有分工:`loop` 无条件循环(唯一能 `break` 出值的)、`while` 条件循环、`for` 遍历迭代器。

**循环标签**用于从内层跳出外层:

```rust
'counting_up: loop {
    loop {
        if count == 2 { break 'counting_up; }   // 直接跳出外层
        break;                                   // 只跳出内层
    }
}
```

标签必须以单引号开头——和生命周期标注同一个符号,但两者毫无关系。

**`for` 优于索引 `while`** 的理由不只是好看:

```rust
let a = [10, 20, 30, 40, 50];
while index < 5 { println!("{}", a[index]); index += 1; }   // 改数组长度就会 panic
for element in a { println!("{element}"); }                  // 长度由迭代器负责
```

索引版本有两个成本:一个和数组脱钩的手工维护的数字(和 **数组、切片与胖指针** 里 `first_word_index` 是同一个毛病),以及每次迭代都要做的边界检查。

Range 是语法糖但**不是数组**:

```rust
for i in 1..=3 { }          // 包含 3
for i in (1..=3).rev() { }  // 倒序
let bad: [i32; 10] = [1..10];    // ✗ 这是「装了一个 Range<i32> 的数组」
```

`1..10` 的类型是 `std::ops::Range<i32>`,不会被自动展开。要造数组用 `std::array::from_fn(|i| ...)`,要运行时决定长度就得用 `Vec`。

## 两个数值陷阱

**浮点相等**:

```rust
assert!(0.1 + 0.2 == 0.3);                          // ✗ 断言失败
assert!((0.1_f64 + 0.2 - 0.3).abs() < 1e-6);        // ✓ 用 epsilon
```

**`as` 是原始类型转换,不是解引用**:

```rust
let m = 5;
let r = &m;
let v: i32 = *r;        // ✓ 沿着引用取值(i32 是 Copy,m 毫发无损)
// let v = r as i32;    // ✗ as 转换的是类型,不是「跟随指针」
```

`as` 还会**静默截断**(`300u32 as u8 == 44`),所以跨宽度转换优先用 `TryFrom`。
