# 01 · 所有权与内存模型

> 一句话:**每个值恰好有一个所有者,所有者离开作用域时值被释放。** 内存回收的时机因此在编译期就完全确定,不需要 GC,也不需要你自己配对 `free`。

## 三种回答同一个问题

「堆上的内存什么时候还回去」这个问题有三种历史答案:

|           | 谁来决定                                | 代价                                       |
| --------- | --------------------------------------- | ------------------------------------------ |
| C / C++   | 程序员手写 `free`                       | 忘了 → 泄漏;早了 → 悬垂;两次 → double free |
| JS / Java | 运行时 GC(标记-清除 / 标记-压缩 / 分代) | 停顿、不可预测的延迟、常驻内存开销         |
| Rust      | 编译器按作用域插入 `drop`               | 你必须在写代码时就说清楚谁拥有什么         |

> **抽象断裂点｜代价没有消失,只是换了付款时间**
> 三种方案付的是同一笔账,区别在**什么时候付**:C 让你在写代码时付(而且经常付错),GC 让你在运行时付(而且付得不确定),Rust 让你在**编译期**付——借用检查器不通过,你今天就得改设计。
> 「零开销抽象」这个说法容易被误读成「不花钱」。准确的说法是:**运行时零开销,代价前移到设计期。** 这跟 **Lecture 1 - What is a Functional Language** 里 OCaml 砍掉 mutation 是同一类交易——都在用「写代码时更难」换「运行时更可信」。
> 长线上值得盯住的是这个模式本身:凡是宣称消除了某项成本的系统,先找它把成本挪到了哪里。

## Stack 与 Heap

栈:LIFO,压栈弹栈都在顶端,**所有数据必须有编译期已知的固定大小**。分配快,因为位置永远是栈顶。

堆:分配器要先找一块够大的空位,标记占用,返回一个指针,还要为下一次分配记账。慢,但能装编译期大小未知的东西。

`String` 的三段结构横跨两边:

```
栈上                          堆上
┌──────────────┐
│ ptr ─────────┼──────────→  [ h, e, l, l, o ]
│ len      = 5 │
│ capacity = 5 │
└──────────────┘
```

字面量 `"hello"` 是第三种位置——既不在栈也不在堆,而在**可执行文件的只读静态区**:

|            | `"hello"`          | `String::from("hello")`  |
| ---------- | ------------------ | ------------------------ |
| 类型       | `&'static str`     | `String`                 |
| 数据在哪   | 可执行文件只读区   | 堆                       |
| 栈上结构   | ptr + len(16 字节) | ptr + len + cap(24 字节) |
| 能否增长   | 不能               | 能                       |
| 赋值行为   | `Copy` 一个引用    | `Move` 所有权            |
| 离开作用域 | 什么都不做         | 释放堆内存               |

## Move:一次让编译器作废原变量的浅拷贝

```rust
let s1 = String::from("hello");
let s2 = s1;
// println!("{s1}");   // ✗ error[E0382]: borrow of moved value: `s1`
```

栈上那三个字段被复制了,堆上的字节**没有**。如果就这样放着,`s1` 和 `s2` 离开作用域时会各释放一次同一块内存——double free。

Rust 的做法不是拷贝堆数据(太贵),也不是引用计数(有运行时开销),而是**直接把 `s1` 从可用集合里划掉**。

> **抽象断裂点｜作废是一个编译期动作,不是运行时动作**
> 「`s1` 被 move 走了」听起来像发生了什么事,其实运行时**什么都没发生**——生成的机器码和一次普通的结构体拷贝一模一样,没有标志位、没有计数器。改变的只是编译器允许你写什么。
> 这是理解 Rust 最重要的一次视角转换:**所有权不是内存里的东西,是类型系统里的东西。** 同一份内存布局,C 会让你用两次,Rust 只让你用一次;差别完全在编译器的账本上,不在硬件上。
> 同一条认知在 **dyn 与 trait object** 里以反方向出现:vtable 是**真的**在内存里,因为静态信息被擦除了,只能落到运行时。**编译期知道的东西不占运行时空间,编译期不知道的东西必须占。** 见 **Box 与 DST** 的信息守恒。

`clone()` 是显式的深拷贝,而且**故意显式**:看到 `.clone()` 就知道这里有一段可能很贵的代码在跑。

`Copy` 是相反的豁免:实现了 `Copy` 的类型(所有整数、浮点、`bool`、`char`、以及元素全是 `Copy` 的数组和元组)赋值时按位复制,原变量继续有效。判据很朴素——**没有任何需要清理的资源**。`Vec` 不可能是 `Copy`,因为它管着堆内存;`[i32; 4]` 是 `Copy`,因为它就是四个整数。

## 所有权与函数

传参和赋值遵循同一条规则:

```rust
fn takes_ownership(s: String) { println!("{s}"); }   // s 在这里被 drop
fn makes_copy(i: i32)        { println!("{i}"); }   // i32 是 Copy,调用方毫发无损
```

想用完还给调用方,就把它返回出去:

```rust
fn take_and_give_back(s: String) -> String {
    println!("{s}");
    s            // 注意没有分号 —— 有分号就变成语句,函数返回 ()
}
```

所有权的时间线是 `s1 → 参数 s → s2`,堆上的字节一次都没动过,动的只是「谁负责释放它」这个记账。

## 部分移动

移动的粒度是**字段**,不是整个值:

```rust
let t = (String::from("hello"), String::from("world"));
let _s = t.0;               // 只移走了 t.0
println!("{:?}", t.1);      // ✓ t.1 还在
// println!("{:?}", t);     // ✗ t 作为整体已经不完整
```

结构体同理——这就是 **struct、impl 与 self 的四种形态** 里 `..user1` 更新语法只作废部分字段的原因。
