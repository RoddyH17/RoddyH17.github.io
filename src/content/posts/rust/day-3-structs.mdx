# Day 3 · Structs and Methods

The first two days used only built-in types. Today I defined my own: `struct` groups related values into a new type, and `impl` attaches methods to it.

> 📁 Today's code: [`day3/structs/`](https://github.com/RoddyH17/rust_learn/tree/main/day3/structs) · 📝 Notes: [`day3/NOTES.md`](https://github.com/RoddyH17/rust_learn/blob/main/day3/NOTES.md)

## Grouping data into a type

```rust
struct User {
    username: String,
    email: String,
    sign_in_count: u64,
    active: bool,
}
```

The code states directly what a "user" is made of. Compared to four separate variables, the data now has a name and a fixed shape. One detail: mutability applies to the whole instance. Either the whole thing is `mut`, or all of it is read-only. You cannot mark a single field as mutable.

## Methods: functions that belong to a type

```rust
impl Rectangle {
    fn area(&self) -> u32 {
        self.width * self.height
    }
}
```

`&self` is the borrowing from Day 2: the method borrows the instance it is called on, and does not take ownership.

A function in an `impl` block without `self` is called an associated function. It is called as `Rectangle::square(20)` and is commonly used as a constructor.

## A first look at moves

The struct update syntax `..user2` takes the remaining fields from another instance. String fields are **moved** by this — ownership of the data transfers to the new instance — so `user2.email` is no longer usable afterward. Moves and ownership deserve their own day; this was a first encounter.

## Notes on the day

A pattern after three days: each new Rust concept builds on the previous ones. `&self` is borrowing; struct update syntax is a move. Tomorrow: enums, `match`, and `Option<T>` — how Rust expresses "there may be no value".
