# 03 · 数组、切片与胖指针

> 一句话:**数组的长度是类型的一部分,切片是「指向其中一段的引用」。** 切片没有所有权,所以借用规则原封不动地作用在它身上。

## 三个容易混的类型

| 类型            | 长度什么时候知道      | 能否作为值存在       |
| --------------- | --------------------- | -------------------- |
| `[T; N]` 数组   | 编译期,**写在类型里** | 能                   |
| `[T]` 切片本体  | 运行时                | **不能**——它是 DST   |
| `&[T]` 切片引用 | 运行时,存在胖指针里   | 能(日常写的都是这个) |

```rust
let a5 = [1, 2, 3, 4, 5];
let ok:  &[i32] = &a5[0..2];      // ✓
// let bad: [i32] = a5[0..2];     // ✗ [i32] 是 DST,栈帧不知道要留多少字节
```

`[i32; 5]` 和 `[i32; 6]` 是**两个不同的类型**。长度进类型这件事的直接后果:数组不能改长度,只能改值。要变长就用 `Vec`(数据在堆上)。

## 数组是 Copy,Vec 是 Move

```rust
fn update(mut arr: [i32; 3]) { for i in 0..3 { arr[i] = 0; } }

let a = [10, 20, 30];
update(a);
println!("{a:?}");        // 还是 [10, 20, 30] —— 函数改的是拷贝
```

`i32` 是 `Copy`,所以 `[i32; 3]` 整个也是 `Copy`。想真的改到调用方那一份,得传 `&mut`:

```rust
fn update_mut(arr: &mut [i32; 3]) { for i in 0..3 { arr[i] = 0; } }
```

`Vec` 永远不可能是 `Copy`——它管着堆内存,按位复制会导致两个 `Vec` 指向同一块堆(double free),深拷贝又是隐藏的开销。Rust 两个都不选,所以只能 move。见 **所有权与内存模型**。

## 切片解决的问题:一个和数据脱钩的返回值

先看不用切片的写法:

```rust
fn first_word_index(s: &String) -> usize { /* 返回第一个空格的下标 */ }

let mut s = String::from("hello world");
let end = first_word_index(&s);   // 5
s.clear();                         // s 现在是 ""
println!("{end}");                 // 还是 5 —— 但已经没有任何字符串能让它有意义
```

`end` 是一个**独立的数字**,编译器不会帮你维护它和 `s` 的一致性。返回切片就不一样:

```rust
fn first_word(s: &str) -> &str { /* 返回 &s[0..i] */ }
```

返回值是一个借用,`s.clear()` 需要 `&mut s`,而借用还活着——编译器直接拒绝。

> **抽象断裂点｜把不变式绑进类型,而不是靠记忆维护**
> 两种写法算的是同一件事,差别在**「这个数字属于那个字符串」这条关系存在哪里**:一个存在程序员脑子里,一个存在类型系统里。
> 这是整门 Rust 课反复出现的同一个动作(见 **基础数据结构手写实现** 的「签名即语义」):把约定搬进编译器能检查的位置。而它的边界同样清楚——**查找算法** 里二分查找的「已排序」就搬不进去,因为**类型能表达「这是什么」,很难表达「这满足什么」**。
> 这里搬得动,是因为「属于」是一个**指称关系**,可以用借用表示;那里搬不动,是因为「已排序」是一个**关于值的性质**,需要依赖类型才能表达。这条分界线值得单独记住:**关系可以类型化,性质通常不行。**

## 胖指针:切片引用是两个字

普通引用 = 1 个字(只有地址);切片引用 = 2 个字 = 首元素指针 + 长度。

```rust
let chars: [char; 3] = ['中', '国', '人'];
let cslice = &chars[..2];
assert_eq!(std::mem::size_of_val(&cslice), 16);   // 不是 8
```

注意不是 8:数组本身是 2 × 4 = 8 字节,但 `cslice` 是**引用**——指针 8 + 长度 8 = 16。而且这个 16 与它引用了多少元素无关。

完整的胖指针家族与 `?Sized` 机制见 **Box 与 DST**。

## 切片语法

```rust
let s = String::from("hello world");
&s[0..5]      // "hello",左闭右开
&s[6..11]     // "world"
&s[..2]       // 起点是 0 可以省
&s[3..]       // 终点是结尾可以省
&s[..]        // 全部
```

数组也能切,机制完全一样:

```rust
let slice = &a5[1..3];
assert_eq!(slice, &[2, 3]);
```

## 常用方法

```rust
nums.len()            nums.is_empty()       nums.contains(&3)
nums.starts_with(&[1, 2])
v.swap(0, 2)          v.reverse()
[1, 2].repeat(2)      ["a","b","c"].join("-")
for w in nums.windows(3) { }     // 以 3 为窗口滚动
```

`windows(n)` 值得单记:它把「相邻元素之间的关系」变成可迭代的对象,做差分、滑动统计、检测单调性都靠它。

## 动态生成数组

```rust
let a: [i32; 10] = std::array::from_fn(|i| (i + 1) as i32);
```

`from_fn` 接受一个「下标 → 元素」的闭包,编译器从左边的类型标注推断出 `T = i32, N = 10`。注意:**长度仍然是编译期确定的**,动态的是元素的计算方式。要长度也在运行时决定就得用 `Vec`:

```rust
let n = 10;
let a: Vec<i32> = (1..=n).collect();
```

`|i| ...` 是闭包,等价于一个没有名字的小函数;闭包的详细讨论(以及为什么闭包只能用 `dyn` 装进同一个 `Vec`)见 **dyn 与 trait object**。
